# 安全与隐私

## 数据性质

系统保存人像照片、模特身份标签、角色信息、访问码、评分和备注，默认都应按私密内容处理。仓库、日志、备份、监控和测试环境不得泄露这些数据。

## 当前安全机制

- 管理员密码用 PHP `password_hash` / `password_verify` 处理。
- 模特访问码为随机 6 位数字字母，并按 IP 哈希进行失败限流。
- Session Cookie 使用 `HttpOnly`、`SameSite=Lax`，HTTPS 下启用 `Secure`。
- 所有 POST API 校验 CSRF token。
- 管理员与模特分别鉴权，图片读取还校验资源归属。
- 原图位于 Web 根目录之外，通过受控 PHP 接口读取。
- SQL 使用 PDO 预处理语句。
- 响应设置 `X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy` 和 `Permissions-Policy`。
- 上传按内容识别 MIME，文件以服务器生成的随机名称保存。

## 威胁与注意事项

### 访问码强度

6 位访问码换取了现场使用便利性，不适合作为长期公开链接。必须保留失败限流，避免在 URL、日志、分析平台和截图中不必要地暴露访问码。活动结束后可重新生成访问码；未来可增加过期时间。

### 文件上传

不要信任文件扩展名和浏览器 MIME。继续使用内容检测，只允许明确支持的图片格式；存储名不可采用用户文件名。解码图片时需考虑压缩炸弹和超高像素导致的内存耗尽。

### 图片输出

不要把 `originals/`、`previews/` 或 `thumbs/` 配成公开静态目录。即使缩略图也属于私密内容，必须由 `photo` API 校验身份和照片归属。

### 永久删除

活动和模特删除会同时删除数据库与文件。攻击者若获得管理员 Session，破坏性很大。应使用强管理员密码、HTTPS、安全的服务器账号，并定期进行离线或版本化备份。未来优先实现软删除/回收站。

### 日志与异常

生产响应不要输出堆栈、文件系统路径、SQL、密码哈希或访问码。服务器日志也应避免记录完整请求体和敏感查询参数，并限制保留时间与访问权限。

## 部署检查

- HTTPS 强制跳转，Cookie 确实带 Secure。
- 数据目录不在公开根目录，直接猜测 URL 无法访问。
- PHP 不显示详细错误给浏览器，错误写入受保护日志。
- 目录权限采用最小权限；Web 用户只能写数据目录，不能修改应用源码。
- 定期备份数据库与原图，备份加密且执行恢复演练。
- Nginx 和 PHP 上传限制符合预期，不允许任意脚本上传执行。
- 管理员退出、Session 过期、下载开关和跨模特访问均经过验证。

## 漏洞处理

发现可能泄露照片或绕过身份验证的问题时，先限制暴露面并保存证据，不要在生产数据上继续试探。修复应包括：根因、受影响范围、是否需要更换访问码/管理员密码、是否需要使现有 Session 失效，以及部署后的回归测试。
