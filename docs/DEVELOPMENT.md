# 开发指南

## 本地启动

要求 PHP 8.0+，并启用 PDO SQLite、GD 和 fileinfo。

```bash
export PHOTO_SELECTOR_DATA_DIR="$(mktemp -d /tmp/photo-selector-dev.XXXXXX)"
php -S 127.0.0.1:8080 index.php
```

请始终使用 Web 根目录之外的临时数据目录，不要提交测试数据。若需要反复测试破坏性操作，请每次使用新建的临时数据目录，并在测试结束后清理。

## 修改原则

当前应用集中在 `index.php`：

1. 文件顶部：PHP 配置、数据目录、数据库建表。
2. 后端辅助函数：响应、输入、Session、CSRF、限流、图片解码和派生图。
3. API 路由：根据 `$_GET['api']` 和请求方法分派。
4. 页面 HTML/CSS。
5. 原生 JavaScript：登录、管理、上传队列、模特图库和查看器。

修改时先定位现有辅助函数，避免建立第二套身份、输入或图片处理逻辑。数据库变更应保持老数据库可启动，并在文档中说明迁移和回滚。

## 静态检查

最低要求：

```bash
php -l index.php
git diff --check
python3 -m unittest discover -s tests -v
```

集成测试使用 PHP 内置服务器与仓库外独立临时数据库，不会连接生产站点；CI 用 Ubuntu 24.04 安装 PHP CLI、SQLite 与 GD 并执行同样的检查。

提交前还应搜索是否误加入数据或凭据：

```bash
git status --short
git ls-files | grep -E '\.(sqlite|db|log|bak)$|(^|/)(originals|previews|thumbs)/'
```

## 自动化覆盖范围

`tests/test_integration.py` 覆盖首次设置、活动与模特创建、中文文件名上传下载、原图字节一致性、跨模特读写隔离、评分备注持久化、下载权限以及重新生成访问码后的旧 Session 撤销。它不能替代实际浏览器交互、手机适配、EXIF 方向与高像素资源耗尽的人工验收。

## 人工验收矩阵

### 初始化与身份

- 空数据目录首次打开时可设置管理员密码。
- 管理员密码错误会失败，正确密码进入管理端。
- 退出后不能继续调用管理 API。
- 正确访问码不区分大小写；错误码触发限流但不泄露码是否接近正确。

### 活动与模特

- 创建活动后名称与日期显示正确。
- 创建模特需要活动、CN、角色；自动生成 6 位访问码。
- 可修改 CN 和角色、重新生成访问码、切换下载权限。
- 删除确认文案明确；只用测试数据验证级联删除。

### 上传

- 同时选择多张 JPEG/PNG/WebP，每张都有独立进度。
- 同时在途请求不超过当前并发数 3。
- 超过 30 MiB、不支持类型或损坏图片显示单张失败。
- 失败项可手动重传，不需要重传成功项。
- 文件名包含中文、空格时仍可上传并在下载时正确命名。

### 图片方向与旋转

- 普通横向 JPEG 显示正确。
- 相机竖拍、带 EXIF Orientation 的 JPEG 在缩略图与大图都竖直显示。
- 管理员左右旋转后缩略图和大图更新。
- 手动旋转后下载原图，原始文件内容和 EXIF 保持不变。

### 模特选片

- 模特只能看到自己照片，不能修改 URL 读取其他模特照片。
- 缩略图可打开大图；上一张、下一张、键盘键和滑动切换正常。
- 评级 1–5 星和备注自动保存，刷新后仍存在。
- 管理端能看到新的评级与备注，并可按要求排序。
- 下载关闭时没有可用的原图下载；开启时下载原文件名正确。
- 页面中不存在完成选片或已完成按钮。

### 响应式

至少检查一个桌面视口、一个约 390px 宽手机竖屏，以及手机横屏：

- 大图完整显示，不被裁切，也不溢出屏幕。
- 关闭按钮不被刘海/安全区遮挡。
- 下载按钮在上一张/下一张上方。
- 上一张和下一张保持同一行且可点击。
- 长备注可以输入和滚动，不遮挡关键按钮。

## 调试提示

- 浏览器只显示“服务器处理失败”时，先查看网络面板中的 HTTP 状态和响应正文，再查 PHP-FPM 错误日志。
- 上传失败优先检查 Nginx `client_max_body_size`、PHP `upload_max_filesize` / `post_max_size`、目录权限、GD 和 PHP 内存。
- 竖图错误时分别检查原图 EXIF、派生图是否旧缓存、`photos.rotation` 和 `DERIVATIVE_VERSION`。
- 修改派生图算法后旧图片未变化，通常需要提升 `DERIVATIVE_VERSION` 或清理测试数据的派生图；不要删除原图。

## 推荐的后续工程化

1. 为每个 API 建立使用临时数据目录的集成测试。
2. 用浏览器自动化覆盖管理员上传、模特评分和手机查看器。
3. 将永久删除改成可恢复回收站。
4. 在有测试保护后拆分 PHP 服务层和静态资源，同时保留简单发布产物。
